Ontology specification · version 0.1.0

MODAVIS Ontology Network

A modular semantic standard for physical, digitized, and virtual musical instruments: their identity, changing states, components, evidence, scholarly assertions, audio regions, and processing provenance. Pipe organs are represented through a dedicated specialization of the instrument-neutral model.

Network overview

The publication separates durable domain semantics from database internals and application-specific exchange mechanics. Public terms keep stable, unversioned IRIs; immutable release artifacts receive version IRIs.

In scope

  • Stable identity and multilingual naming
  • Instrument-neutral components and contextual functional roles
  • States, configurations, events, evidence, assertions, and provenance
  • Digital surrogates, fixed audio regions, and virtual-instrument identity
  • Contextual heritage recognition and checksum-fixed knowledge revisions
  • Pipe-organ specialization without making it the universal model

Deliberately separate

  • Operational database tables and workflow state
  • VAO ZIP paths, archive rules, and application profiles
  • Authentication, authorization, cache, and deployment behavior
  • Unreviewed external alignments and mutable vocabulary snapshots

Module architecture

Core supplies common identity and temporal foundations. Domain modules reuse it without importing the VAO container vocabulary.

Related exchange standard

Virtual Acoustic Object · VAO 0.4.0

VAO is a downstream container and application profile, not an ontology module. Its final co-release binding uses MODAVIS 0.1.0 terms directly and adds an exact VAO-owned mapping.

MODAVIS OntologiesInstruments, components, states, configurations, evidence, assertions, events, provenance, and governed concepts.
→
VAO · .vaoOne ZIP64 object containing the semantic graph, audio, 3D models, animations, interaction data, paradata, analyses, rights, and fixity.
→
OrgRec & VAOMOrgRec uses VAO as its primary exchange format. VAOM is the instrument-neutral manager, validator, and authoring environment.
Co-release interoperability contractVirtual pipe-organ example

Dependency direction: VAO 0.4.0 binds to the immutable MODAVIS 0.1.0 network and owns the conservative mapping graph. MODAVIS does not import VAO; the two validation regimes remain separate.
